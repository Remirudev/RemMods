## 1. Decisions and principles

- [both] Architecture: Rust `remmods-core` (all logic, synchronous, no Tauri), `remmods-ipc` (DTOs + `AppError`, specta, no Tauri), a thin `src-tauri` shell and a React 19 + Mantine 9 UI. Identifier `com.remirudev.remmods`.
- [both] Repo `Remirudev/RemMods`: public, but only you can change it. No collaborators; Issues, Wiki and Discussions off; Pull requests set to "Collaborators only" (Settings → General → Features; new in Feb 2026); a ruleset on `main` without bypass blocks force pushes and deletion and requires pull requests with green CI, so Windows can't break silently. Anyone can read the code; nobody else can push, merge, open issues or open pull requests. Public GitHub Releases feed the updater and the AUR. Verified 2026-11-01: your own PRs pass "Collaborators only". Dependabot's are still UNVERIFIED (its first run proposed nothing under its default cooldown); if it blocks them, PRs go back to open, since only you can merge anyway.
- [both] Merge gate: `main` is protected; PRs need `ci / linux` (ubuntu-24.04), `ci / windows` (windows-2025), `ci / smoke` (the built app launched on both) and `ci / policy`, plus `fs-matrix` from P2. A red Windows job blocks like a red Linux job.
- [both] Never Linux-first: on-disk rules, `safe_fs` semantics, name validation, profile and settings formats, archive safety. PRs touching these carry tests that run on both OSes.
- [Linux] May land Linux-first: Linux-only features (graphics fallback, AppImage env cleanup, Flatpak/Snap Steam) and features whose Windows half needs a real Windows machine.
- [Windows] A Linux-first feature still builds and passes tests on Windows and either works or reports `unsupported` via `platform_info().features`. It gets an entry in `docs/windows-gaps.md` (Issues are off; PR template: "Windows impact: none / covered by CI / windows-gap WG-n"); a release needs zero open entries marked release-blocking. Real-PC Windows tests come later (no Windows PC yet; your call): until the Windows checklist has run on a real PC or VM, Windows builds are labelled "beta, CI-tested only".
- [both] Same behaviour everywhere: Windows name rules, case-insensitive collision checks and never-overwrite renames on both OSes. IPC bindings and UI strings are byte-identical.
- [both] Supported: [Linux] glibc ≥ 2.39 (Ubuntu 24.04+, Mint 22+, Debian 13+, Fedora 40+, SteamOS 3.7+, Arch/CachyOS), published in the README and release notes. [Windows] 10 22H2 and 11, x64, WebView2 Evergreen.
- [both] Platform code lives only in `remmods-core/src/platform/`, `src-tauri/src/os/` and the per-OS Tauri configs. CI fails on `cfg(windows|unix|target_os)` anywhere else.
- [both] Pure-Rust crates preferred: the CachyOS linker bug did not reproduce today (plan graph and blake3 linked in dev and LTO with rustup 1.94.1 and system 1.99.1), but C/asm stays a toolchain risk. pkg-config system libraries are fine; CI guards the rest (§10).
- [both] Safety: writes only inside the 3 mod roots, RemMods' app dirs and the Trash (checked `Scope`); Steam files are read-only. Removal is always a rename; permanent delete needs a second confirm. Batches are all-or-none and journaled, and one cross-process lock serialises writers. Extra roots outside Paks (P6+) need an explicit amendment of this rule.
- [both] Compatibility: folders following the usual TEKKEN 8 conventions keep working; the exact rules are §7. RemMods writes no `profiles.json` except its own store.
- [both] Least privilege: no fs, shell or process plugins. The webview can only call RemMods commands listed in one capability file.
- Out of scope for v1: macOS, Flatpak/Snap packages, Steam Deck Game Mode, a standalone Windows exe, installing UE4SS, Lua/DLL mods.

## 4. Rust core

- **Modules**: `platform`, `safe_fs`, `game`, `mods`, `archive`, `install`, `profiles`, `settings`, `ops`, `paths`, `error`. A `Core` facade owns the scope, settings, OpGate and lock. Root kinds share a `RootStrategy` (scan rows, `plan_toggle` → ops, conflicts): Pak, Logic and Loose now, Deploy for extra roots later.
- **Scope**: `Scope::check` requires an absolute path, no `.`/`..`, a location strictly below a canonical root (Mods, ~mods, LogicMods, app dirs; the Trash only via `platform::trash`) and no symlink or junction component. Roots compare as canonical components, case-insensitively on Windows.
- [Windows] Every `std::fs` call gets a verbatim `\\?\` path from `platform::fs_path`: std passes short paths unprefixed, so Win32 strips a trailing dot or space and `Foo.` would hit `Foo` (verified). `dunce` is for display only.
- **ModRef**: rows carry an opaque, session-only `ModRef` string token `1|kind|fileid|paksid|path` (the Paks file id or location generation instead of the canonical root, key texts instead of raw bytes; also the table row id). Commands take ModRef + expected key and need exactly one match in a fresh scan, else `Stale` and the UI refreshes. Keys are for profiles only.
- [both] Ambiguous keys: rows sharing a key (`Mods/Cool` + `mods/Cool`; `X` + `.disabled_X` + `.DISABLED_X`) block every mutation, are skipped by profile apply (listed in the diff) and go to Repair (rename or merge).
- **Names**: `validate_name` applies Windows rules to new names on both OSes: no `<>:"/\|?*`, control or bidi characters, trailing dots or spaces, reserved names `CON, PRN, AUX, NUL, CONIN$, CONOUT$, COM1-9, LPT1-9` and COM/LPT + `¹²³` (stem before the first dot; COM0/LPT0 stay allowed), more than 255 UTF-8 bytes, `.disabled_`, the temp pattern. Collisions use `fold_key` = NFC(full case fold(NFD)); order is (fold key, bytes); paths past 259 characters warn, measured in the game's view (`S:\` + the path below the Steam library on Linux, `Z:` + the path otherwise, the real path on Windows). Existing names are only flagged, never blocked: what Win32 rejects (empty, dot names, > 255 UTF-16 units, forbidden or C0 characters, trailing dot or space, reserved names) is `InvalidName` (Reveal blocked); what only RemMods rejects (> 255 bytes, DEL/C1, bidi, Logic names > 245 bytes, payload file names > 253 bytes) is `NameNotPortable`, a warning only, as Windows accepts them. U+2028/U+2029 and other invisible characters are not rejected in P1.
- [both] Non-Unicode names ([Linux] raw bytes from legacy unzip/7z, [Windows] unpaired surrogates) become issue rows with a lossless escaped key (`\\`, `\xHH`, `\u{HHHH}`; injective, checked over 93,436 inputs) and a "Rename to a valid name" repair; keys never use `to_string_lossy`.
- **Rename**: `rename_noreplace` stays within one folder and never replaces anything. [Linux] `renameat2(NOREPLACE)`; on EINVAL (ntfs-3g, NFS) files use `link` + `unlink` (a crash leaves two names for one inode, never an empty live `.pak`) and folders an exclusive empty-dir placeholder. [Windows] `MoveFileExW(\\?\…, 0)`.
- [both] Case-only renames always go through a journaled temp name and are verified by re-listing. Per kernel source a direct one is a silent no-op on exFAT/vfat/casefold (UNVERIFIED by test; the fs-matrix covers it).
- **Batch**: `rename_batch` runs a preflight that writes nothing (sources exist; targets and case-insensitive siblings are absent; no duplicate or chained targets), renames in order and rolls back in reverse on failure. Logic batches rename the folder first, so they fail before any file changes.
- [Windows] The preflight opens every file with DELETE access, so a holder without `FILE_SHARE_DELETE` (the game) fails before anything changes. Share-compatible handles (antivirus, indexer, Explorer preview) pass it but still block folder renames (NTFS rule; verified). Failures return `BatchError { failed, rolled_back, stuck }`; the caller always rescans.
- **Errors**: `platform::classify` maps `io::Error` to `OsErrorClass` (InUse, AccessDenied, NoSpace, ReadOnlyFs, CrossDevice, NameTooLong, Unsupported, Other), because raw codes collide (Windows 5/32/33 are EIO/EPIPE/EDOM on Linux). One thiserror enum per module (`FsError`, `ArchiveError`, `GameError`, `InstallError`, `ProfileError`) with stable snake_case codes builds on the classes; raw codes only go to the log.
- **Retry**: [Linux] one attempt. [Windows] Never while the game holds the file. File renames retry InUse ≤1.6 s; folder renames (commit, rename, Logic toggle, set-aside, cleanup) treat AccessDenied as `FolderBusy` and retry ≤30 s behind a toast with Cancel that names the holder via Restart Manager ("close TEKKEN 8" only if it is the game).
- **Trash**: `platform::trash` only ever renames. The trash crate is out: on Windows it lets the shell show its own "delete permanently?" dialog, and on Linux it copies + deletes across devices (verified in 5.2.9).
- [Linux] Own freedesktop mover: the home trash or else `$topdir/.Trash-$uid` (created 0700 where allowed), whichever shares the mod's mount (statx mount ID; `rename(2)` fails across mounts) and device (st_dev; btrfs subvolumes differ). It writes the `.trashinfo` first, then `renameat2(NOREPLACE)` into `files/`.
- [Windows] Own recycle on a fresh STA thread: `IFileOperation` with `FOF_NO_UI | FOF_ALLOWUNDO | FOFX_RECYCLEONDELETE | FOFX_EARLYFAILURE`, no `FOF_WANTNUKEWARNING`, and a sink whose `PreDeleteItem` returns `E_ABORT` without `TSF_DELETE_RECYCLE_IF_POSSIBLE` (Electron's approach; verified). Names Win32 normalises never reach the shell: Trash and Reveal are blocked and Repair offers a verbatim rename.
- [both] Anything else (other device, no usable topdir trash, bin off or too small, network drive) returns `TrashUnavailable { size }`: "Delete permanently" (second confirm) or Cancel. Nothing is copied, and nothing is destroyed without RemMods' token.
- **Set-aside**: permanent delete and install-replace first make the mod inert (`-x` batch) and rename it to a hidden, journaled `_<name>_tmp_<32hex>` in the same root (atomic; fails cleanly on Windows while files are busy). Delete then removes it in the background; leftovers stay hidden and inert in Repair. The delete token binds to the ModRef, not the key.
- **Atomic writes**: `write_atomic` uses atomic-write-file (temp file in the same dir, fsync of file and dir); [Windows] the whole write is retried on InUse; a corrupt file is first copied to `.backup.yyyyMMdd_HHmmss`. Clippy `disallowed-methods` bans the `std::fs` mutators (`rename`, `remove_*`, `write`, `copy`, `create_dir*`, `File::create`) outside `safe_fs`.
- **Lock**: `remmods.lock` (app-local data) via std `File::try_lock` (flock / LockFileEx): exclusive for mutations, app-data writes and recovery, shared for scans; held → `Busy`. It also covers a second GUI (single-instance needs D-Bus on Linux; verified) and the CLI. JSON stores: lock → re-read → merge → `write_atomic` with a `revision`.
- **Journal**: one record per batch, fsynced before the first op: ops with pre/post paths, placeholders before creation, the files staging made inert, owner PID + session id. Recovery runs under the lock for dead owners only, reads each op's state from disk and rolls back by default; a dead owner's install staging is discarded, not resumed (P4 A5).
- **Archives**: `archive::open` → `list()` (headers only) → `extract(plan, staging, progress, cancel)`. One backend file per crate; rars sits behind cargo feature `rar-builtin`; library `extract()` helpers are never used. Multi-volume sets, spanned `.z01` and passwords return typed `unsupported` errors with a hint (install from an extracted folder) until after 1.0.
- [both] Archive names: `\` is a separator in every format (Windows tools write it) before NFC, traversal checks and `validate_name`. UTF-8 when flagged or valid, else CP437, with a per-archive encoding override in the preview (Shift_JIS, GBK, Big5, EUC-KR, IBM866, windows-1251).
- [both] Entry safety: traversal, absolute, drive and UNC paths are never allowed. Links and devices are skipped. Identical duplicates are deduped, differing ones block, and case clashes go to a picker. "Rename automatically" fixes Windows-invalid names together with companion files.
- [both] Write discipline: `create_new` in staging, bytes capped at the declared size, free space ≥1.1× (fs4), decoder memory ≤ min(4 GiB, 50 % RAM; 2 GiB when RAM is unknown), checked per format from header properties, checksums verified, mtimes kept, owners/permissions ignored. Staging is removed on error or cancel.
- **Install**: `inspect` lists and validates, detects the root, strips the root segment and single wrapper folders, checks all roots + `.disabled_` + fold keys, and groups variants. `stage` writes the payload as inert `-x` and journals each file it made inert.
- [both] `commit` (one journaled all-or-none batch through `WriteGuard::rename_batch_replacing`, under the lock; P4 A4): set aside any old folder, rename staging into place, strip `-x` from the journaled files only (archive-shipped `*.pak-x` options stay off), then trash the aside folder as a separate retryable step; without Trash it stays hidden and inert in Repair. No drive type blocks an install.

## 7. On-disk rules (TEKKEN 8 mod-folder conventions)

- [both] Roots `Paks/Mods` (Standard), `~mods` (Legacy) and `LogicMods` (Logic) are matched case-insensitively. They are created only on install, with that exact casing.
- [Linux] Two roots that differ only in case (`Mods` + `mods`) are both listed and flagged. Wine resolves the exact case first and lists both (verified), so the game probably loads both (UNVERIFIED in-game); their mods share keys and are ambiguous.
- [both] A mod is one immediate subfolder of a root. Its key is `{Kind}:{Name}` (e.g. `Standard:NeonSkin`), compared case-sensitively. Loose paks in a root are RemMods-only rows keyed `Loose:{Mods|~mods|LogicMods}/{stem}` from the root kind, not its on-disk spelling (`mods/X.pak` → `Loose:Mods/X`); byte-identical loose keys are ambiguous.
- [both] A Logic mod's name is its folder name without `.disabled_`. In Mods/~mods, a `.disabled_X` folder is an ordinary pak mod named `.disabled_X`, with an info issue. A LogicMods folder named exactly `.disabled_` is a row with key `Logic:` and an issue.
- [both] Pak disable appends lowercase `-x` to every `.pak/.ucas/.utoc/.sig` at any depth (case-insensitive): `Foo.pak` → `Foo.pak-x`. The folder is never renamed, and `.txt` files are left alone.
- [both] Pak enable strips `-x` from `.pak-x/.ucas-x/.utoc-x/.sig-x/.txt-x` (`.txt-x` because existing folders carry it): only the files RemMods' last disable recorded in `mod-meta.json` while that record matches disk, otherwise all of them.
- [both] State: `.pak` only = Enabled; `.pak` and `.pak-x` = Partial; `.pak-x` only = Disabled; neither = "no pak files". Hand-disabled variants survive an off/on toggle in RemMods.
- [both] Logic disable renames `X` → `.disabled_X` (first) and adds `-x` to the paks inside, in one batch; enable reverses both. UE4SS source shows BPModLoaderMod loads paks from every first-level subfolder, dot-folders included. Your decision: keep this double disable plus the repair below; if the P2 in-game test shows dot-folders are not loaded, switch to rename-only.
- [both] Logic anomalies are shown as such: prefixed but with live paks = "disabled by name only – still loaded" (fix offered); unprefixed with only `-x` paks = "enabled by name, not loaded" (repair offered). RemMods never creates `X` next to `.disabled_X`.
- [both] Staging and set-aside folders follow the usual hidden naming, `<root>/_<label>_tmp_<32 lowercase hex>` (≤255 bytes). They are inert and journaled; only journaled folders of dead owners are ever removed.
- [both] `modinfo.json` reading: BOM sniffing (UTF-8/16/32; serde_json rejects BOMs), else lossy UTF-8; case-sensitive PascalCase keys, parsed strictly (every occurrence of the four keys must be a string or null, depth ≤ 64, the last valid duplicate wins); the exact file name first, else a single ASCII-case-insensitive match on both OSes (several variants → ignored with an issue); files over 1 MiB are ignored (a RemMods guard); missing, null or blank → `1.0`, `Misc`, empty, `Unknown` (so a blank saves as the default). An unparsable file is ignored, flagged and copied to `modinfo.json.backup.<yyyyMMdd_HHmmss>` before RemMods' first write.
- [both] `modinfo.json` is written only on user edit: exactly `Version, Category, Description, Author`, 2-space indent, UTF-8 without BOM, LF on both OSes (readers accept CRLF too), non-ASCII and HTML-sensitive characters as uppercase `\uXXXX` (a fixed escaping, pinned by its golden test). RemMods-only data goes to `mod-meta.json`.
- [both] Sizes: logical, including `-x` and sidecar files, formatted without digit grouping; a 0-byte mod shows "0 B".
- [both] Conflicts: RemMods links rows pairwise and compares `fold_key`, not a plain ASCII case-insensitive name (it also unifies ß/ss/ẞ, ſ/s, U+212A/k, U+212B/å, U+2126/ω, ﬁ/fi and NFC/NFD, which a per-UTF-16-unit upper-casing compare keeps apart). Prefixed Logic rows with live paks take part, since the game loads them (UNVERIFIED): valid only if the P2 in-game test shows that paks in dot-folders load; otherwise fall back to an enabled-set comparison where prefixed Logic rows never conflict. RemMods adds per-pair details.
- [both] Loose copies: a live copy of a mod's pak or companion file at the Paks top level or in an Unmanaged folder is flagged (game paks and `-x` files are not copies).
- [both] Another mod manager's `profiles.json` is imported read-only and idempotently (matched by its `Id`) as `exclusive` profiles, because that format's apply disables every mod not in `EnabledMods` (its empty "Default" disables all). A null `EnabledMods` is tolerated and keys without `:` become `Standard:<key>`. That file is never written.
- [both] Other tools: RemMods rescans before every change, and never-overwrite renames make races fail cleanly. While `ModManager.exe` runs (another mod manager; detected on both OSes, Wine included), a neutral notice shows and delete/rename/overwrite need confirmation. Renames in RemMods update keys only in RemMods' profiles.

## 8. Robustness rules

All rules apply on both OSes.

- Rows are addressed by opaque ModRefs. When `X` and `.disabled_X` both exist, the shared key is ambiguous: actions on it are blocked and it is sent to Repair.
- Every action ends with a fresh snapshot, failed ones included, and a LogicMods toggle reports its result like any other. A rename onto an existing name gives `AlreadyExists`.
- Disabling a LogicMods mod sets both the `.disabled_` prefix and `-x`, since the game may still load a prefixed folder; a "still loaded" check runs afterwards.
- Disable leaves `.txt` files alone; enable also strips `-x` from `.txt-x`.
- Enable switches on only what RemMods disabled; variants the user left off stay off and the row shows Partial.
- Profiles are never written implicitly: the UI shows "unsaved changes since last apply" and saving is an explicit action.
- Applying a profile shows a diff modal, takes an auto snapshot first and runs as one all-or-none batch. Saved profiles are additive, imported ones are exclusive.
- Nothing auto-applies, default profiles included. Parsing is tolerant (`"EnabledMods": null` is read as an empty list); an unparsable `profiles.json` is backed up and replaced; store errors are shown while the app keeps running.
- Removal moves to the Trash (always a rename). Permanent delete needs a second confirmation and runs through an atomic set-aside, so a failure never leaves half a live mod.
- Every rename goes through `validate_name`: reserved names, trailing dots, `.disabled_Y` and temp names are refused. Case-only renames are journaled two-step.
- Metadata: a blank field means the default, BOM'd files are decoded, a corrupt file is backed up before the first write, save errors show as toasts, and the Added date and source live in `mod-meta.json`.
- Install strips wrapper folders and the root segment, checks every root, prefix and fold key, applies one duplicate policy to every format and keeps archive-shipped `-x` options off.
- Repair lists crash leftovers: RemMods' own can be resumed or trashed, foreign ones revealed or trashed.
- Staging is ignored by the watcher and inert for the game.
- One install job per process (single-instance keeps one process). Extraction runs outside the app lock, with brief exclusive locks for staging and commit and re-checks of target, location and fingerprint before the commit (P4 A6). When root detection cannot read an archive, the result is a typed error and nothing is installed.
- `config.lua` beside paks marks a LogicMods mod; other scripts show "UE4SS script mod, not supported in v1".
- Launch goes through `steam://rungameid/1778820`, never the exe directly.
- The game folder must contain the TEKKEN 8 exe and Paks; its location is stored in `settings.json`, so game updates keep it.
- Loose files are rows of their own, archives inside Paks form an "Archives inside Paks" group (Install/Reveal/Trash), and unmanaged files an "Unmanaged (still loaded)" list.
- A refresh is one single-flight scan pass with per-mod errors; success messages are toasts.

## 14. Risks and mitigations

- rars is young (≈5 months, AI-written, spec partly reverse-engineered) → exact pin, `rar-builtin` flag, checksums, weekly diff against unrar (deferred at P4, A14; crafted fixtures run on both OSes instead), folder install, tool fallback after 1.0.
- Fast-moving pins (zip, rars, TanStack Table 9, Mantine 9, tauri-specta RC) → exact versions, one adapter file per crate, grouped upgrades with CI on both OSes.
- No Windows PC (real-PC tests later; your call) → windows-2025 runs every core test, a launch smoke and a silent NSIS install; Windows builds stay labelled "beta, CI-tested only" until the checklist has run on a real PC or VM.
- Engine behaviour is UNVERIFIED (dot-folders, depth, case-variant roots, live renames) → the P2 in-game tests come before load order or any relaxed running-game rule.
- Unsigned Windows builds: Smart App Control blocks them with no per-app exception and no longer needs a clean install (verified) → README, SHA256SUMS, Microsoft submission, SignPath via `signCommand` after the first release. No pak-signature bypass features (SignPath eligibility).
- Removal edge cases (antivirus holding fresh paks, no Recycle Bin, other devices) → 30 s folder retries with Cancel and a named holder; movers only rename; `TrashUnavailable` is a choice; set-aside keeps failures inert.
- WebKitGTK blank windows or crashes on NVIDIA/Wayland (tauri#9394 open) → auto env, crash marker with a FORCE_SHM → software chain, `.desktop` safe mode; needs an NVIDIA tester (your GPU is AMD). GTK3's lack of fractional scaling is offset by the in-app UI scale.
- AppImage env leaking into Steam/the game → one `host_command` that filters path lists and resets cwd, checked in P5.
- notify 8 loses Windows overflow events → focus rescans and post-command snapshots; notify 9 when stable.
- Races with other tools → never-overwrite renames, rescan before every change, `ModManager.exe` banner. Two RemMods processes → the cross-process lock.
- The glibc 2.39 floor excludes Ubuntu 22.04, Debian 12 and Mint 21 → stated up front; lowering it means building on 22.04 with its frozen WebKitGTK 2.50 and re-testing the UI, so only on demand.
- Updater key loss or leak → password, protected environment, offline backup.
- Format changes by other mod tools → core tests pin the on-disk rules (§7); golden tests compare parsed values.
